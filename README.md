# Symmetry, not information, determines what a predictive cognitive map collapses

**Manas Venkata Sai Ravulapalli**

Code and paper for the study of how landmark symmetry shapes the spatial code learned by a
predictive recurrent network. The paper is in `project5_symmetry/Report/biorxiv/`
(`main.tex` + `supplementary.tex`, with compiled PDFs).

---

## The claim in one paragraph

A recurrent network trained to predict its next observation develops place-cell-like spatial
tuning [(Levenstein et al. 2024)](https://doi.org/10.1101/2024.04.28.591528), but this is
validated in arenas where every position looks unique. Real arenas are symmetric. We show that
whether the learned code *folds* onto the arena's symmetry quotient is set by whether the
head-direction encoding is **invariant** under the arena's symmetry group, not by how much
information the encoding carries. Two encodings matched at one bit but differing in invariance
(`axis` vs `parity`) separate completely in a `C2` arena and are indistinguishable in an
asymmetric one; the fold appears directly in single-cell rate maps (fields repeat at the
symmetry-related locations); it hits the group-theoretic `1/|G|` ceiling; it requires a
*predictive* rather than reconstructive objective; it survives a noisy compass; and it
reproduces the place-field repetition [Grieves et al. (2016)](https://doi.org/10.1002/hipo.22532)
observed across identical compartments in rodents.

## Repository layout

```
project5_symmetry/          the study
  environments/             arenas (SymmetryArena, compartments, topology), trajectory gen,
                            head-direction encodings
  experiments/              training drivers (vmap ensemble)
  analysis/                 read-out scripts (one per result) + the figure generator
  evaluation/metrics.py     sRSA, isotypic power, place-field coherence, ...
  Report/biorxiv/           the paper (main.tex, supplementary.tex, figures/)
  Report/data/              every result CSV behind the paper (see its README)
utils/                      the model: pRNN_th (Architectures.py), the cell (thetaRNN.py),
                            checkpoint (de)serialisation, the trajectory data layer
tests/                      pytest suite (210 tests) pinning the correctness-critical pieces
```

Large data (trained checkpoints, raw trajectory `.npz`) is **not** in the repo; it is kept
locally and gitignored (`outputs/`, `*.pt`, `*.npz`). The paper's numbers are reproducible from
the committed CSVs, and the checkpoints can be regenerated by the training step below.

## Reproduce the paper

### 0. Sanity check

```bash
python3 -m pytest tests/ -q          # 210 tests; pins the ensemble, metrics, and readouts
```

### 1. Train (GPU)

Training uses one batched job per computation graph (`torch.func.stack_module_state` +
`vmap`), so a whole sweep is a single compute-bound run. Trajectories are generated on first use
and cached under `--data-root`.

```bash
# Main sweep: s1/s2/s4 arenas x {full, parity, axis, const} head-direction encodings.
# n=10 for s1/s2, n=8 for s4 (seeds 0-9; s4 uses 0-3,6-9).
python3 project5_symmetry/experiments/run_hd_invariance.py \
    --seeds s1=6 s2=6 s4=4 --out runs/hd_invariance --data-root data/symmetry
python3 project5_symmetry/experiments/run_hd_invariance.py \
    --seeds s1=4 s2=4 s4=4 --seed-offset 6 --out runs/hd_invariance --data-root data/symmetry

# Prediction-horizon control (k = 0,1,3 in the C2 arena):
python3 project5_symmetry/experiments/run_hd_invariance.py \
    --seeds s2=6 --hd-modes full parity axis const --k 0 --out runs/horizon/k0 --data-root data/symmetry
#   ... repeat with --k 1, --k 3 ...

# Noisy-compass robustness (30% +/-90 deg corruption):
python3 project5_symmetry/experiments/run_hd_invariance.py \
    --seeds s2=6 --hd-modes full parity axis const --hd-noise 0.3 --n-steps 30000 \
    --out runs/hd_noisy --data-root data/symmetry

# Compartments (Grieves), initialisation study, and topology arenas, one ensemble:
python3 project5_symmetry/experiments/run_multi.py \
    --groups compartment init kaiming topology --out runs/multi --data-root data
```

Each run writes `runs/.../<condition>/<seed>/ckpt_final.pt` with metadata the analysis reads.

### 2. Analyse (CPU, on the checkpoints) -> CSVs

```bash
D=project5_symmetry/analysis
python3 $D/run_phase_decoding.py --runs runs/hd_invariance --data-root data/symmetry \
    --group c2 --out project5_symmetry/Report/data/phase_full_n10.csv        # Table 2
python3 $D/run_map_quality.py   --runs runs/hd_invariance --out project5_symmetry/Report/data/map_quality_groupB.csv
python3 $D/run_compartments.py  --runs runs/multi/compartment --data-root data/compartment \
    --out project5_symmetry/Report/data/compartments.csv                     # Grieves
python3 $D/field_stats.py       --runs runs/hd_invariance --data-root data/symmetry \
    --out project5_symmetry/Report/data/field_stats.csv --dump field_counts.npz
python3 $D/run_replay.py        --runs runs/horizon/k1 --out project5_symmetry/Report/data/replay_k1.csv
python3 $D/run_sequenceness.py  --runs runs/hd_invariance --out project5_symmetry/Report/data/sequenceness.csv
python3 $D/run_tda.py           --runs runs/multi/topology --data-root data/topology --out tda_topology.csv
python3 $D/rate_maps.py         --runs runs/hd_invariance --conds s1/full s2/full s2/axis s4/const \
    --out rate_maps.npz         # for the place-cell figure
python3 $D/manifold_pc.py       --runs runs/multi/topology --data-root data/topology --out manifold_pc.npz

# --- neuroscience + geometry read-outs (CPU) ---
RD=project5_symmetry/Report/data
python3 $D/remapping.py         --runs runs/hd_invariance --data-root data/symmetry --out $RD/remapping.csv
python3 $D/cell_types.py        --runs runs/hd_invariance --data-root data/symmetry --out $RD/cell_types.csv
python3 $D/prospective.py       --runs runs/horizon/k0 runs/horizon/k1 runs/horizon/k3 runs/hd_invariance \
    --data-root data/symmetry --hd full --out $RD/prospective.csv          # anticipatory-firing null
python3 $D/manifold_robustness.py --runs runs/hd_invariance --data-root data/symmetry --out $RD/manifold_robustness.csv
python3 $D/topology_robustness.py --runs runs/multi/topology --data-root data/topology --out $RD/topology_robustness.csv
python3 $D/diffusion_maps.py    --topo-runs runs/multi/topology --topo-data data/topology \
    --fold-runs runs/hd_invariance --fold-data data/symmetry \
    --out-csv $RD/diffusion_maps.csv --out-fig project5_symmetry/Report/biorxiv/figures/figS_diffusion.pdf
python3 $D/run_compartments4.py --runs runs/multi/compartment4 --data-root data/compartment4 --out $RD/compartments4.csv
```

### 3. Figures

Every figure is generated from the CSVs/npz above, so no numbers are hand-entered.

```bash
python3 project5_symmetry/analysis/make_paper_figures.py \
    --data project5_symmetry/Report/data \
    --figs project5_symmetry/Report/biorxiv/figures
```

(Point `--data` at a directory holding the CSVs plus `rate_maps.npz`, `manifold_pc.npz`,
`field_counts.npz` from step 2 to regenerate the rate-map and manifold panels as well.)

### 4. Build the paper

```bash
cd project5_symmetry/Report/biorxiv
# main.tex uses the eLife class, which requires XeLaTeX (unicode-math, opensans, STIX)
xelatex main && bibtex main && xelatex main && xelatex main
pdflatex supplementary && pdflatex supplementary
```

## Hardware

Training is a single compute-bound GPU job (measured on an RTX 5090: a 64-model ensemble at
80k steps in ~90 min). A modern 8 GB+ GPU suffices; CPU works for the analysis and figures. The
analysis and figure steps need no GPU.
